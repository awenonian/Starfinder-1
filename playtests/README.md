# Playtests

Records of the GM being run, kept so the prompt can be edited from evidence
instead of from theory.

**This directory is testing apparatus, not part of the game and not part of the
campaign.** It ships in the template because the prompt is still being built; it
can be deleted from a copy that's only playing.

## The log command

During a session the player can say, out of character:

> `log: you confirmed my theory about the sister`

The GM appends it verbatim to `playtests/current.md` and carries on. It does not
discuss it, defend the thing flagged, or apologise — a GM that argues with the
report is doing the same over-compliance one level up, and it costs the player
the thing they were about to say next.

Entries are cheap. "log: that felt flat" is a useful entry. So is "log: good"
— knowing what landed matters as much as knowing what broke, and is harder to
reconstruct afterwards.

## Why the player, not the GM

The GM noticing its own sycophancy is precisely what the research says it can't
reliably do: the failure doesn't feel like capitulation, it feels like the scene
going well. So the GM's job here is stenography, not self-assessment. Anything
it flagged about itself would be the entries it was already able to catch,
which are the ones that matter least.

## Running one

Copy `TEMPLATE.md` to `current.md` before the session. Rename it to `NN-short-name.md`
afterwards. See `docs/playtesting.md` for the protocol and for what to do with a
finished run.
